Usa Editorial OS desde un asistente de IA, sin perder el control del plan.

El MCP es un puente local entre un asistente compatible y el mismo Supabase que usa Editorial OS. Puede consultar y modificar planner, biblioteca, notas, producción, escenarios y marcas, manteniendo el mismo estado compartido.

Descargar instalador MCPCódigo del MCPGuía de la app

Qué es, en simple

Tú hablas con un asistente ↓ El asistente llama herramientas MCP ↓ Editorial OS MCP lee o modifica Supabase ↓ La Web / PWA / Mac ve esos mismos cambios

No es un bot haciendo clics en la interfaz. Trabaja directamente sobre la fuente de datos compartida de Editorial OS.

Instalación paso a paso

1

Abre Terminal en tu Mac

No necesitas clonar el repo manualmente.

2

Pega el instalador

cd ~/Downloads curl -fL "https://lordjeferies.github.io/editorial-os/INSTALL_EDITORIAL_MCP.command" -o INSTALL_EDITORIAL_MCP.command chmod +x INSTALL_EDITORIAL_MCP.command ./INSTALL_EDITORIAL_MCP.command
3

Escribe el usuario de Supabase

El Project URL, la anon key pública y el workspace ya vienen preconfigurados. El instalador sólo te pide email y contraseña.

Si ESA cuenta de Supabase usa la contraseña 4brxs, escribe 4brxs. No significa que todas las cuentas tengan esa contraseña.

4

El instalador prepara el MCP

Descarga el servidor, instala dependencias, valida sintaxis y crea ~/.editorial-os-mcp/.env con permisos privados.

5

Recibe la configuración del host

Al final se copia al portapapeles y también se guarda en tu Escritorio como EDITORIAL_OS_MCP_CONFIG.json.

Cómo conectarlo a un cliente MCP

Configuración genérica

{ "mcpServers": { "editorial-os": { "command": "/Users/TU_USUARIO/.editorial-os-mcp/run-mcp.sh", "args": [] } } }

El instalador genera este bloque con tu ruta real. El lugar exacto donde pegarlo cambia según ChatGPT/Codex/Claude/u otro cliente MCP.

Cómo usarlo según el caso

Caso 1 · Sólo quiero revisar

"Revisa el plan de esta semana. No cambies nada. Dime densidad por día, huecos y posibles problemas."
status→planner→recomendación

Ideal para auditorías. No necesita herramientas de escritura.

Caso 2 · Armar una semana

"Arma una semana con 1–2 piezas por día usando webinar, podcast y testimonios. Conserva los anchors fijos."
leer→buscar/crear→añadir→verificar

El MCP debe respetar fichas fixed y volver a leer al terminar.

Caso 3 · Mover una ficha

"Mueve el carrusel del martes al jueves."
planner_list_week→instanceId→planner_move_content

No se mueve por título ambiguo sin antes resolver el ID real.

Caso 4 · Agregar una corrección

"A esta pieza agrégale una nota: el hook tarda demasiado y debe entrar directo al problema."
buscar identidad→content_add_note

Las notas nuevas se agregan; no se borran las anteriores.

Caso 5 · Cambiar producción

"Marca el reel del miércoles como cambios solicitados y asígnalo a Pamela."
resolver pieza→production_get→production_set

Estados válidos: planned, production, editing, review, changes, approved, scheduled, published.

Caso 6 · Guardar una versión del plan

"Guarda esta semana como escenario Semana Webinar Octubre."
planner actual→scenario_save_current

Después puedes recuperarlo con scenario_apply.

Caso 7 · Aplicar un escenario

"Aplica el escenario Semana Webinar Octubre."
scenario_list→confirmación→scenario_apply

Es una operación amplia: exige confirm: true.

Caso 8 · Crear una marca

"Crea la marca ACME, con Instagram, LinkedIn y YouTube."
brand_list→brand_create

No borra las marcas existentes.

Caso 9 · Backup antes de cambios grandes

"Antes de cambiar toda la semana, exporta un backup lógico."
editorial_backup→cambios

El backup no contiene la contraseña.

Caso 10 · Sólo lectura para IA

EDITORIAL_MCP_READ_ONLY=true

Úsalo cuando quieras que el asistente pueda analizar todo pero no modificar nada.

Criterios que debe seguir el asistente

  • Leer el estado antes de escribir cuando una decisión depende del plan actual.
  • Preservar campos desconocidos del payload; no reemplazar el JSON con un objeto parcial.
  • Usar expectedRevision en secuencias críticas para detectar cambios simultáneos.
  • No borrar fichas fixed salvo instrucción explícita.
  • No vaciar la semana sin confirmación expresa.
  • No eliminar contenido que esté usado en el planner sin revisar referencias.
  • Agregar notas sin destruir notas anteriores.
  • Mantener workspace_key = editorial-os para esta app.
  • Autenticarse como usuario real de Supabase y respetar RLS.
  • No poner service_role, database password ni secretos privados en la PWA o en GitHub.

Qué pasa cuando usas MCP y la app al mismo tiempo

Mismo usuario

La app y el MCP leen/escriben la misma fila user_id + workspace_key. Realtime permite que la app reciba cambios remotos.

Conflictos

El MCP actualiza syncMeta.revision. En operaciones delicadas puede recibir expectedRevision; si cambió mientras trabajabas, debe volver a leer antes de intentar otra escritura.
